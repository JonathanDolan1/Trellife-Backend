# Deploying Trellife (Jonathan's copy)

One Render web service on the free plan, defined in `render.yaml`.
The Express server serves the API under `/api`, socket.io, and the built
React frontend from `public/`.

## Environment variables

| Name | Where the value comes from |
|------|----------------------------|
| `MONGO_URL` | Pasted by hand in the Render dashboard (MongoDB Atlas connection string). Never committed. |
| `SECRET1` | Generated by Render (`generateValue: true`). Signs login tokens. |
| `NODE_ENV` | `production` (set in `render.yaml`). |
| `NODE_VERSION` | `20` (set in `render.yaml`). |
| `DB_NAME` | Optional. Defaults to `trellifeDB`. |
| `GUEST_MODE` | Deliberately not set. When `true`, requests with no login pass as an anonymous Guest. Keep it off on the public demo. |
| `OPENAI_API_KEY` | Deliberately not set. The AI board route then answers 503 and the button is hidden. |

The server refuses to start if `MONGO_URL` is missing.

## Database access

The app uses only the `trellifeDB` database (collections `user` and `board`),
so the Atlas user needs `readWrite` on `trellifeDB` and nothing more.
Render's free plan has no fixed outbound IP address, so Atlas Network Access
must allow `0.0.0.0/0` for the service to connect.

## Updating the frontend

The frontend lives in the separate repo JonathanDolan1/Trellife. Build it into
this repo's `public/` folder and commit the result:

```bash
cd ../Trellife && npm ci && npx vite build --outDir ../Trellife-Backend/public --emptyOutDir
```

The AI button appears only when the frontend is built with `VITE_ENABLE_AI=true`.

## Free plan behavior

The service sleeps after about 15 minutes without traffic. The first request
after that waits for a cold start.
